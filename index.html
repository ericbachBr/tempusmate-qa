🔎 Super Auditoria de Qualidade de Código

Claude Sonnet 5 + Gemini + ChatGPT GPT-5.6 Sol • análises independentes → consenso.

Objetivo

Não procurar UI bugs primeiro. Procurar duplicação de regra, acoplamento, divergência semântica, risco de regressão e dívida criada durante a estabilização.

Caso de estudo já comprovado

Calendar grouping vs Invoice eligibility: Profile “ab” + manual “ab” eram representados de formas diferentes em duas camadas. Uma dizia “duas identidades”; outra dizia “elegíveis juntos”. Esse é exatamente o padrão que a auditoria deve procurar no resto do sistema.

Escala

P0 data/financial integrity • P1 high regression risk • P2 architectural debt • P3 cleanup

Foco

  • Invoice client loading/default resolution vs Quote client loading/default resolution
  • Expense client linking vs Invoice/Quote identity semantics
  • Agenda/Calendar manual-name fallback
  • Calendar → Invoice vs Generate from Shifts
  • Quote → Invoice mapping and snapshot preservation
  • Rate/overtime defaults duplicated across modules
  • Financial calculation duplication / double-counting risk
  • Global State coupling and hidden mutations
  • DOM orchestration mixed with domain logic
  • Persistence/localStorage scattered across modules
  • Dead/superseded functions after recent fixes
  • Structural/regex tests that should be runtime tests
